# Feature review: the whole of Hivo (November 2026)

**Why:** the owner felt the features went out too fast and were overlooked. This is a feature-level review, not a style pass: where does a feature not do its job for a real crew with real data? It covers desktop, crew website and phone app.

**How (2026-11-01):** eight reviewers read the code in parallel, one per area, each with the roadmap, the guardrails and its slice of the code:

- Library
- Launch Kit
- Crew
- Digger and People
- The desktop side of the phone features
- App shell and dashboard
- Phone app features
- Phone app robustness, from scratch

The serious findings were then checked against the code by hand (marked **✓ checked**). Line numbers are from `main@a50e333` (desktop) and the phone branch with #168/#169. Nothing here was run on real data yet. "PLAUSIBLE" means the code path is real but the trigger needs a real machine or phone.

**Severity:** **BREAKS** = the feature fails its job or loses data · **FRICTION** = works, but the user hits a wall · **POLISH**.

**Already fixed** while this ran: BandLab names (#168), phone audit batch (#169), and a regression of mine in #168 (share text could still be cut inside an emoji, fixed in #169).

## 3. Dead ends and silent failures (friction)

**Library:**
- A folder filter can stay set while its pane is hidden: "No songs match" with nothing to click.
- Focus rescans and the post-render rescan swallow errors.
- "Save as new version" copies only tags and stage.
- Re-renders pile up as `(1)`, `(2)`… with no cancel.
- Create-song can error after the file already exists, and a retry then says "already exists".
- Missing samples and plugins can't be acted on.
- Big libraries: FL files are re-parsed on every scan, sample libraries are re-indexed on every focus, and the table isn't virtualized.

**Launch Kit:**
- "Write captions & brief" wipes hand-edited captions with no confirm.
- The picked FLUX cover isn't used in shorts, and nothing checks for a final 3000×3000 cover.
- "Move to Release" shows right after export and is never nudged after the date.
- Calendar entries use the raw file name.
- Captions say "pre-save in bio" with no pre-save.
- The cover prompt's title scrub fails on accented titles, so "Été" can reach Cloudflare.

**Crew:**
- Every launch re-writes every shared song (`lastPushed` lives in memory), so 300 songs means 300 writes and 1,200 realtime events.
- The first drag in a column renumbers every card with one request per card.
- Sync runs 1.5 s after any edit, including typing notes.
- Column and release errors are silently turned into empty lists.
- In sample-data mode the crew board goes stale.
- There's no transfer of ownership (the message says "hand one over"), no display-name change, and no crew rename on the desktop.
- The invite flow still depends on the Supabase dashboard (closed sign-up).

**Digger and People:**
- Without a Gemini key there's no Dig and no BPM or key at all.
- Dig state isn't saved across restarts.
- One bad file aborts the whole dig.
- YouTube results that can't be embedded show an error inside the player.
- Beat notes are lost on rename.
- Hand-edited or cloud-copied lead files vanish without a word.
- More than 5,000 beats are silently truncated, and m4a/opus files are ignored.
- Re-lookup overwrites profiles, and they can't be edited.
- The Spotify token cache survives credential changes.
- The "web search off" pause lasts 30 minutes even after a new key.

**Desktop side of the phone features:**
- Zip stems can't be attached to an existing song, and attached files are renamed after the title.
- More than 20 stems are dropped silently when continuing in FL.
- A mixdown plus stems plays doubled in the new FL project.
- Closing the main window with the session window open leaves a zombie process.
- The session view loses a song that was renamed.
- Filed items can't be undone, and "Show in folder" exists but isn't wired.
- When the IP or port changes, phones break with no re-address flow.
- Phone sync answers "busy" during any scan.
- Filing is half-applied on failure (a retry duplicates).

**Phone:**
- A finished take can be lost by the on-screen Back.
- Memos can't be played once kept, and nothing prunes sent items.
- Long uploads block note sync, and `goBack` calls `sync()` instead of `requestSync()`.
- The share filters miss `video/mp4` and `octet-stream`, which "Add a file" accepts.
- Big shares show a blank screen while copying.
- A share sent before pairing ends on the pair screen with no "waiting" note.
- A second queued share overwrites the first.
- The library cache is one AsyncStorage row (about 2 MB limit), and search is O(n²).
- Pairing is saved before it's verified, there's no "Open Settings" when the camera is denied forever, and a new QR is ignored while paired.
- Hardware Back on the share screen skips the cache cleanup.
- The 5 s timeout on `/v1/snapshot` and `/v1/notes` is shorter than the desktop's 10 s.
- New items are saved with a 300 ms debounce (a kill loses the record), and nothing sweeps orphan files.
- A corrupt outbox is overwritten by `[]`.
- There's no total-size cap on a share, and "inbox full" holds the whole queue.

**Shell:**
- "Auto-detect FL Studio" does nothing when FL isn't found.
- Picker errors show under the wrong section.
- A failed settings save isn't reported, and edits are lost if the save fails on close.
- Disconnected folders aren't marked in Settings.
- The updater error is raw English and is checked once per launch.
- A workspace from a newer version is re-stamped v2.
- "Edit layout" shows over an empty dashboard.
- One shared error slot (`startupError`) for everything.

## 4. Decisions for you (not plain fixes)

- **Phone protocol v1.2.** Responses aren't tied to their request, so a replay on the LAN could mark a sketch sent and delete it from the phone. Re-pairing the same computer gets a new device id, so everything is re-sent and ideas can be filed twice. Both need the desktop to answer differently: echo the request nonce, and return a stable computer id in `/v1/hello`.
- **Recording in the background.** Keep-awake is easy. A real foreground service (recording with the screen off) needs a permission and a Play declaration.
- **Crew "Who's on what" and per-person last activity** rank people with no action attached. That's the monitoring shape guardrail 3 warns about. Make the rows open that member's songs, or drop the ranking.
- **Tendency blocks built on mtimes.** Label them "approximate", or wait for the stage log and the Pace block.
- **The syllable and bar counter (B3.2).** Build it, or un-tick it.
- **Release safety.** The phone checks for updates unless the build says `play` (fail-open), and signing falls back to the debug key when the secret is missing. Both should fail closed in CI.
